# 3.6 Rules 规则管理

## 功能说明

Rules 管理可以跨应用复用的规则。Prompts 每个应用同一时间只能启用一条，并且会覆盖目标文件；Rules 可以同时启用任意多条，同一条规则还能在不同应用里分别开关。

- 规则内容只在 CC Switch 里保存一份。数据库是唯一事实来源，各应用的 rules 目录只是它的投影：启用、停用、改名、删除时重新投影。
- 支持 **Claude Code**、**Codex**、**Gemini CLI**、**OpenCode** 的用户级（全局）规则。Windows 上没有 Codex 这一列。其他应用不会出现在规则页，也不会写入任何文件。
- 矩阵只显示设置里「在侧栏显示哪些应用」开启的应用；被隐藏的应用仍会在后台同步规则。

## 打开规则页

点击左侧栏的 **规则**。页头右侧只有 **添加规则**。页面有两个页签：

- **已安装**：CC Switch 管理的规则，用「规则 × 应用」矩阵展示。
- **发现**：受支持应用的 rules 目录里已经存在、但还没纳入管理的规则文件。

两个页签右上角都有搜索框，只过滤当前页签。

## 新建与编辑

点页头 **添加规则** 新建；在已安装页点规则名，或点行尾 ⋯ → **编辑**，打开的是同一个对话框。

- **名称**必填，同时就是文件名 `<名称>.md`。在名称框按回车可以直接保存。
- 名称忽略大小写判重；不能包含 `/ \ < > : " | ? *` 或控制字符，不能以 `.` 开头或结尾，也不能使用 Windows 保留名（如 `CON`、`COM1`），最多 80 个字符。
- **内容**用 Markdown 编写，最多 256 KiB。
- 有未保存修改时「保存」才可用；保存过程中不能关闭；未保存关闭会丢弃修改。
- 保存后立即同步到各应用。新规则默认不在任何应用启用，需要到矩阵里勾选。
- 改名等同改文件名：旧文件从各应用目录移除，再按新名称写入。

## 已安装矩阵

行是规则，列是应用。表头和规则名在滚动时固定。

- **行**：复选框、规则名（点击编辑）、正文摘要。没有任何应用启用时显示「未启用」；有写入失败时名称旁出现 ⚠，悬停查看错误。
- **单元格**：点击写入或移除该应用的规则文件。状态分已启用、未启用、写入失败；失败格再点一次即可重试。
- **列头**：显示该应用的启用数量。点开可以全部启用、全部关闭，或切换「只看在这个应用里启用的规则」。批量操作只作用于当前列表（全部 / 筛选 / 搜索结果），完成后有撤销提示。
- **多选**：勾选行首复选框或表头全选框。选中后工具栏变成「已选 N」，可用 **启用到** / **停用** 把选中的规则批量同步到某个应用，或 **取消选择**。
- **筛选**：工具栏左侧有「全部 / 已启用 / 未启用」，可以和列头的按应用筛选叠加。
- **搜索**：匹配规则名称和正文，右上角显示找到的数量。
- **同步到应用**：没有选中行时出现在工具栏右侧，按当前开关重新投影所有规则，修复外部改动造成的不一致。启动 CC Switch、保存规则、切换单元格、删除和导入规则时也会自动同步。
- **行菜单 ⋯**：编辑、删除。删除前会确认，并从各应用移除对应文件。

一条规则都没有时，页面提供 **新建规则** 和 **去发现**。搜索或筛选没有结果时，提供清空搜索 / 清除筛选的按钮。

## 发现与导入

发现页只列出**还没纳入管理**的规则文件；已添加的不会出现在这里。

扫描范围是受支持应用的 rules 目录，只认直接放在目录下的 `.md` 文件；隐藏文件和子目录跳过。文件名不能作为规则名（过长、含 `/`、Windows 保留名或首尾空格等）的文件不会列出。同名文件只显示一行，正文取按 `Claude Code → Codex → Gemini CLI → OpenCode` 顺序读到的第一份。

每行显示文件名、完整路径、正文摘要（跳过 frontmatter 和标题）、发现它的应用图标，以及 **添加** 按钮。搜索匹配名称、路径、摘要和应用名。

点 **添加**：

- 内容导入数据库，并在发现它的每个应用里启用；之后到已安装页编辑。
- 已有同名规则的不会被覆盖（这类文件本来也不会列出来）。
- 同一个文件只导入一次。
- 如果某个应用登记已有文件失败，该应用不会被启用，并给出警告；其他应用照常导入。
- 扫描本身只读；导入才会写数据库、`.cc-switch-rules.json` 清单并投影文件。其他应用里的同名文件会用导入的内容重写，frontmatter 可能被去掉。

右上角 **重新扫描** 刷新列表；窗口重新获得焦点时也会自动刷新。列表数量显示「待添加 N 个」。没有可添加文件时显示「没有待添加的规则」；rules 目录本身为空时提示可以新建规则，或把文件放进去后重扫。

## 规则如何落地：固定三步

不论应用是否原生支持规则，CC Switch 都按同样顺序执行三步：

1. **确认安装位置**：解析应用配置目录下的 `rules` 目录和扩展名（`.md`）。
2. **写入规则文件**：把正文渲染成该应用能读的内容，写入 `<名称>.md`。
3. **让应用读取规则**：Claude Code 原生读取该目录，这一步是空操作；Codex、Gemini CLI 增删 SessionStart hook；OpenCode 增删全局配置里的 rules glob。

第 3 步失败时，第 2 步写入的文件会保留；错误信息会带上步骤号，下次同步只重试失败的部分。某个应用的最后一条规则被停用后，第 3 步会撤销它添加的 hook 或 glob。

## 各应用适配

| 应用        | 读取方式            | 规则目录                        | 第 3 步的改动                                                                                      | 说明                                           |
| ----------- | ------------------- | ------------------------------- | -------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| Claude Code | 原生读取            | `~/.claude/rules/*.md`          | 无                                                                                                 | 保留 YAML frontmatter，`paths:` 可用           |
| Codex       | SessionStart hook   | `~/.codex/rules/*.md`           | `~/.codex/hooks.json` 增加 SessionStart 条目；必要时在 `config.toml` 打开 `[features] codex_hooks` | Windows 不支持，不显示该列；需在 `/hooks` 信任 |
| Gemini CLI  | SessionStart hook   | `~/.gemini/rules/*.md`          | `settings.json` 增加名为 `cc-switch-rules` 的 SessionStart hook                                    | hook 输出严格 JSON 的 `additionalContext`      |
| OpenCode    | `instructions` glob | `~/.config/opencode/rules/*.md` | 在 `opencode.jsonc`（存在时）或 `opencode.json` 的 `instructions` 中增删一条绝对路径 glob          | 保留注释、排版和其他 instructions              |

共同约束：

- 应用通常在**会话启动或首次请求**时读取规则；改完要新开会话，OpenCode 需要重启。
- 只有 Claude Code 原样保留 YAML frontmatter，其他应用都会去掉。
- `rules` 目录跟随设置里覆盖的配置目录。
- hook 应用会把 `rules` 目录里所有 `.md` 注入上下文，包括不是 CC Switch 管理的文件，并按文件名顺序拼接；上下文有限，规则宜短。
- Codex 停用规则不会反关 `codex_hooks`，它可能是你自己打开的。

## 文件归属、冲突与清理

CC Switch 在每个规则目录维护 `.cc-switch-rules.json`，记录自己写过的规则文件名。

- 停用或删除规则时，只删除清单里登记的文件，不会碰你自己放进去的 `.md`；hook 应用启用期间仍会读取它们。
- 不要直接编辑 CC Switch 生成的文件：下次保存、切换开关或启动时会被覆盖。要改就在规则页里改。
- 启用规则时，如果目标位置已有同名文件且不在清单里，同步会报冲突并且不覆盖（内容完全一致时除外）。先到发现页导入，或手动改名后再启用。
- 在设置里切换配置目录后，新目录会重新生成规则文件；旧目录里的文件不会自动删除。
- 清单损坏或含非法文件名时，对应条目会被忽略，不会写到规则目录之外。

## 常见问题

**规则保存了，但应用没有生效？**

- Claude Code：确认 `~/.claude/rules/<名称>.md` 存在，然后新开会话。
- Codex：确认不在 Windows 上，`~/.codex/hooks.json` 的 SessionStart 里有 cc-switch 条目，`config.toml` 中 `codex_hooks = true`，并在 `/hooks` 信任；然后新开会话。
- Gemini CLI：确认 `~/.gemini/settings.json` 里有 `cc-switch-rules` 的 SessionStart hook，然后新开会话。
- OpenCode：确认全局配置的 `instructions` 里有 rules 目录的 glob，然后重启 OpenCode。

**规则和提示词会冲突吗？**

不会，写入位置不同：Claude Code 的提示词是 `CLAUDE.md`、规则在 `rules/`；Codex 和 OpenCode 的提示词是 `AGENTS.md`，规则分别通过 hook 和 `instructions` 引入；Gemini CLI 的提示词是 `GEMINI.md`，规则通过 hook 注入。

**为什么矩阵里看不到某个应用？**

- Windows 上 Codex 不支持规则。
- 其他应用尚未适配规则，不会出现在规则页。
- 也可能是设置里「在侧栏显示哪些应用」把它隐藏了；隐藏只影响界面，已经启用规则的同步不受影响。
