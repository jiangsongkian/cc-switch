# 3.6 Rules ルール管理

## 機能概要

Rules はアプリ間で再利用できるルールを管理します。Prompts はアプリごとに 1 件しか有効にできず対象ファイルを上書きしますが、Rules は何件でも同時に有効にでき、同じルールをアプリごとに個別にオン・オフできます。

- ルールの内容は CC Switch に 1 つだけ保存されます。データベースが唯一の正で、各アプリの rules ディレクトリはその投影です。有効化・無効化・名前変更・削除のたびに書き直します。
- **Claude Code**、**Codex**、**Gemini CLI**、**OpenCode** のユーザーレベル（グローバル）ルールに対応しています。Windows では Codex の列は表示されません。その他のアプリはルール画面に表示されず、ファイルも書き込まれません。
- マトリクスに表示される列は、設定の「サイドバーに表示するアプリ」に従います。非表示のアプリでもルールの同期は続きます。

## Rules 画面を開く

サイドバーの **ルール** をクリックします。ヘッダー右側には **ルールを追加** だけがあります。画面には 2 つのタブがあります。

- **インストール済み**: CC Switch が管理しているルールを「ルール × アプリ」のマトリクスで表示します。
- **検出**: 対応アプリの rules ディレクトリに既にあるが、まだ管理されていないルールファイルを表示します。

どちらのタブにも右上に検索ボックスがあり、現在のタブだけを絞り込みます。

## ルールの作成と編集

ヘッダーの **ルールを追加** で新規作成します。インストール済みでルール名をクリックするか、行末の ⋯ → **編集** でも同じダイアログが開きます。

- **名前**は必須で、そのままファイル名 `<名前>.md` になります。名前欄で Enter を押すと保存できます。
- 名前は大文字・小文字を区別せずに重複を判定します。`/ \ < > : " | ? *` や制御文字は使えず、`.` で始めたり終えたりできません。Windows の予約名（`CON`、`COM1` など）も使えず、80 文字までです。
- **内容**は Markdown で、256 KiB までです。
- 変更があり、エラーがないときだけ **保存** を押せます。保存中は閉じられず、保存せずに閉じると変更は破棄されます。
- 保存するとすぐに各アプリへ同期されます。新しいルールはどのアプリでも無効で、マトリクスでチェックする必要があります。
- 名前の変更はファイル名の変更です。古いファイルは各アプリのディレクトリから削除され、新しい名前で書き直されます。

## インストール済みマトリクス

行がルール、列がアプリです。スクロール時はヘッダーとルール名が固定されます。

- **行**: チェックボックス、ルール名（クリックで編集）、本文のプレビュー。どのアプリでも無効なら **無効** と表示され、書き込みに失敗した行は名前の横に ⚠ が出て、ホバーでエラーを確認できます。
- **セル**: クリックするとそのアプリのルールファイルを書き込み・削除します。状態は「有効 / 無効 / 書き込み失敗」で、失敗したセルをもう一度クリックすると再試行します。
- **列ヘッダー**: そのアプリで有効な件数を表示します。開くと、すべて有効化、すべて無効化、そのアプリで有効なルールだけに絞り込む切り替えができます。一括操作は現在の一覧（すべて / 絞り込み / 検索結果）にだけ作用し、実行後に元に戻すトーストが出ます。
- **複数選択**: 行のチェックボックスまたはヘッダーの全選択を使います。選択中はツールバーが **N 件選択** に変わり、**有効化先** / **無効化** で選択したルールをアプリへ一括反映し、**選択を解除** で解除できます。
- **絞り込み**: ツールバー左側の「すべて / 有効 / 無効」は、列ヘッダーのアプリ絞り込みと重ねて使えます。
- **検索**: ルール名と本文に一致し、見つかった件数を検索欄に表示します。
- **アプリに同期**: 行を選択していないときツールバー右側に表示されます。現在のスイッチに従ってすべてのルールを再投影し、外部での変更による不整合を直します。起動時、保存時、セルの切り替え時、削除時、取り込み時にも自動で同期します。
- **行メニュー（⋯）**: 編集、削除。削除は確認後に各アプリからファイルを取り除きます。

ルールが 1 件もないときは **新規ルール** と **検出へ** を表示します。検索・絞り込みで一致しないときは、検索語や絞り込みを解除するボタンを表示します。

## 検出と取り込み

検出タブには、まだ**管理されていない**ルールファイルだけが表示されます。追加済みのファイルは表示されません。

対応アプリの rules ディレクトリ直下にある `.md` ファイルだけを対象にし、隠しファイルとサブディレクトリは除外します。ファイル名をルール名として使えないファイル（長すぎる、`/` を含む、Windows の予約名、前後の空白など）も一覧に出ません。同じ名前のファイルが複数のアプリにある場合は 1 行にまとめ、本文は `Claude Code → Codex → Gemini CLI → OpenCode` の順で最初に読めたものを使います。

各行にはファイル名、完全なパス、本文のプレビュー（フロントマターと見出しを除く）、見つかったアプリのアイコン、**追加** ボタンが表示されます。検索は名前、パス、プレビュー、アプリ名に一致します。

**追加** をクリックすると:

- 内容がデータベースに取り込まれ、見つかったすべてのアプリで有効になります。以後はインストール済みで編集します。
- 同名のルールが既にある場合は上書きしません（そもそも一覧に出ません）。
- 同じファイルは 1 回だけ取り込みます。
- あるアプリで既存ファイルの登録に失敗した場合、そのアプリは有効化されず警告が出ますが、他のアプリはそのまま取り込まれます。
- スキャン自体は読み取りのみです。取り込み時にデータベース、`.cc-switch-rules.json` マニフェスト、各アプリのファイルを書き込みます。他のアプリにある同名ファイルは取り込んだ内容で書き直されるため、フロントマターは削除されることがあります。

右上の **再スキャン** で一覧を更新します。ウィンドウが再びフォーカスされたときにも更新されます。件数は「未追加 N 件」と表示されます。追加できるファイルがないときはその旨が表示され、rules ディレクトリ自体が空のときは新規作成かファイルを置いて再スキャンするよう案内します。

## ルールのインストール: 固定された 3 ステップ

アプリが rules をネイティブに読むかどうかに関係なく、CC Switch は常に同じ 3 ステップを同じ順序で実行します。

1. **インストール先を確認**: アプリの設定ディレクトリにある `rules` ディレクトリと拡張子（`.md`）を解決します。
2. **ルールファイルを書き込む**: 本文をアプリが理解できる形式に変換し、`<名前>.md` として書き込みます。
3. **アプリに読ませる**: Claude Code はディレクトリをネイティブに読むため何もしません。Codex と Gemini CLI は SessionStart hook を追加・削除します。OpenCode はグローバル設定の rules glob を追加・削除します。

ステップ 3 が失敗してもステップ 2 のファイルは残り、エラーには失敗したステップが含まれます。次回の同期では失敗した部分だけを再試行します。あるアプリで最後のルールを無効にすると、ステップ 3 で追加した hook や glob を元に戻します。

## アプリ別の適応方法

| アプリ      | 読み込み方式           | ルールの書き込み先              | ステップ 3 の変更                                                                                                 | 補足                                                  |
| ----------- | ---------------------- | ------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| Claude Code | ネイティブ             | `~/.claude/rules/*.md`          | なし                                                                                                              | YAML フロントマターを保持（`paths:` が使える）        |
| Codex       | SessionStart hook      | `~/.codex/rules/*.md`           | `~/.codex/hooks.json` に SessionStart エントリを追加。必要なら `config.toml` の `[features] codex_hooks` を有効化 | Windows 非対応（列が出ない）。`/hooks` での信頼が必要 |
| Gemini CLI  | SessionStart hook      | `~/.gemini/rules/*.md`          | `settings.json` に `cc-switch-rules` という SessionStart hook を追加                                              | hook は厳密な JSON の `additionalContext` を返す      |
| OpenCode    | `instructions` の glob | `~/.config/opencode/rules/*.md` | `opencode.jsonc`（あれば）または `opencode.json` の `instructions` に絶対パスの glob を 1 件追加・削除            | コメント、書式、他の instructions を保持              |

共通の制約:

- 多くのアプリは**セッション開始時または最初のリクエスト時**にだけルールを読みます。変更後は新しいセッションを開き、OpenCode は再起動してください。
- YAML フロントマターをそのまま保持するのは Claude Code だけで、他のアプリでは削除されます。
- `rules` ディレクトリは設定で上書きした設定ディレクトリに従います。
- hook を使うアプリは、CC Switch が管理していないものを含め `rules` ディレクトリのすべての `.md` をファイル名順に連結して注入します。コンテキストを消費するため、ルールは短く保ってください。
- Codex でルールを無効にしても `codex_hooks` は元に戻しません（自分で有効にしていた可能性があるため）。

## ファイルの所有、競合、クリーンアップ

CC Switch は各 rules ディレクトリに `.cc-switch-rules.json` を置き、自分が書いたルールファイル名を記録します。

- ルールの無効化・削除時は、マニフェストに記録されたファイルだけを削除します。自分で置いた `.md` は削除せず、hook アプリはルール有効期間中それらも読みます。
- CC Switch が生成したファイルを直接編集しないでください。次回の保存、切り替え、起動時に上書きされます。変更はルール画面で行ってください。
- 有効化先にマニフェストにない同名ファイルがある場合、同期は上書きせず競合としてエラーにします（内容が完全に同じ場合は除く）。先に「検出」から取り込むか、手動で名前を変えてから有効化してください。
- 設定で構成ディレクトリを切り替えると、新しいディレクトリにルールファイルを再生成します。古いディレクトリのファイルは自動削除されません。
- マニフェストが壊れている、または安全でないファイル名を含む場合、その項目は無視され、rules ディレクトリの外には書き込みません。

## よくある質問

**ルールを保存したのにアプリで反映されない**

- Claude Code: `~/.claude/rules/<名前>.md` があることを確認し、新しいセッションを開いてください。
- Codex: Windows でないこと、`~/.codex/hooks.json` に cc-switch の SessionStart エントリがあること、`config.toml` で `codex_hooks = true` になっていること、`/hooks` で信頼していることを確認し、新しいセッションを開いてください。
- Gemini CLI: `~/.gemini/settings.json` に `cc-switch-rules` の SessionStart hook があることを確認し、新しいセッションを開いてください。
- OpenCode: グローバル設定の `instructions` に rules ディレクトリの glob があることを確認し、OpenCode を再起動してください。

**ルールとプロンプトは競合しますか？**

いいえ、書き込み先が異なります。Claude Code はプロンプトが `CLAUDE.md`、ルールが `rules/`。Codex と OpenCode はプロンプトが `AGENTS.md` で、ルールはそれぞれ hook と `instructions` から読み込まれます。Gemini CLI はプロンプトが `GEMINI.md`、ルールは hook で注入されます。

**マトリクスにアプリが出ないのはなぜですか？**

- Windows では Codex がルールに対応していません。
- その他のアプリはまだ対応しておらず、ルール画面には出ません。
- 設定の「サイドバーに表示するアプリ」で隠している可能性もあります。非表示は画面だけに影響し、有効にしたルールの同期は続きます。
